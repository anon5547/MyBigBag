ทั้งหมดนี้อ่านจากสกรีนช็อตที่คุณส่งมาโดยตรง ไม่ใช่การเดา
เรียงตามความร้ายแรง มากไปน้อย ไม่มีอวย

## 1. 🔴 Trailing Distance แคบกว่าสเปรด — นี่คือจุดตายอันดับหนึ่ง

ค่าจากพาเนล: `Lot = 0.05`, `Trailing Distance = $0.50`

XAUUSD 1 lot = 100 ออนซ์ → 0.05 lot = 5 ออนซ์
ราคาขยับ $1.00 = กำไร/ขาดทุน **$5.00**

```
Trailing Distance $0.50  ÷  $5.00 ต่อ 1 หน่วยราคา  =  ราคาขยับแค่ $0.10
```

สเปรดทองที่โบรกเกอร์รีเทลปกติอยู่ที่ **$0.20 – $0.40**

> **Trailing stop ของคุณแคบกว่าสเปรดตัวเอง 2–4 เท่า**

ผลคือทุกไม้ที่กำไรแตะ $1.00 (Trailing Start) จะโดนปิดทันทีด้วย noise
ไม่ใช่เพราะเทรนด์กลับ ดูตัวเลขปิดจริงจาก log ของคุณ:

```
$1.32  $11.28  $0.37  $5.78  $1.70  $2.74  -$0.78  $1.93  $0.36
```

ค่าเฉลี่ยกำไร ≈ **$2.74** ขณะที่ `SL Money = $10`

**อัตราชนะที่ต้องมีเพื่อแค่เสมอตัว:**
```
10 / (10 + 2.74) = 78.5%
```

โมเดล ML บนกราฟ M5 ที่ทำ 78.5% แบบยั่งยืน — ไม่มีอยู่จริง
ระบบนี้กำไรอยู่เพราะยังไม่เจอไม้ที่ชน SL ติดกันหลายไม้ ไม่ใช่เพราะมี edge

**แก้ยังไง:** ใช้ `InpTrailMode = SNP_TRAIL_ATR` — trailing ผูกกับ ATR
ไม่ใช่ผูกกับจำนวนเงิน ที่ไม่รู้ว่าสเปรดกว้างแค่ไหน

## 2. 🔴 Threshold 0.35 ไม่ได้กรองอะไรเลย

ค่า Meta Confidence ที่ log พิมพ์ออกมา:

```
0.50  0.37  0.43  0.49  0.55  0.61  0.58  0.33  0.53
```

จาก 9 ค่า มี **8 ค่าผ่านเกณฑ์** ตัวกรองที่ปล่อยผ่าน 89% ไม่ใช่ตัวกรอง

Meta-model ตาม Lopez de Prado มีไว้เพื่อ **ไม่เทรด** เป็นส่วนใหญ่
ถ้ามันปล่อยผ่านเกือบทุกไม้ แปลว่าอย่างใดอย่างหนึ่ง:

- threshold ต่ำเกินไป (แก้ได้)
- meta-model ไม่ได้เรียนรู้อะไร (ต้องเทรนใหม่)
- meta-model ถูกเทรนบน primary prediction แบบ **in-sample** ทำให้มันเชื่อ primary
  มากเกินจริง (นี่คือความผิดพลาดที่พบบ่อยที่สุดใน meta-labelling)

**แก้ยังไง:** `tools/train_two_tier.py` เทรน meta บน **out-of-fold** prediction เท่านั้น
และพิมพ์ตาราง threshold sweep ให้เลือกค่าจากข้อมูลจริง ไม่ใช่ตั้งเอา

## 3. 🔴 ทุกสัญญาณเป็น SELL — และราคากำลังขึ้น

จาก log ของคุณทั้งหมด:

| เวลา | BUY | SELL | ราคา |
|---|---|---|---|
| 13:30 | 19.98% | 80.02% | 4349.32 |
| 13:35 | 10.31% | 89.69% | 4353.50 |
| 14:00 | 8.93%  | 91.07% | 4362.91 |
| 14:10 | 17.86% | 82.14% | 4365.89 |
| 14:15 | 14.01% | 85.99% | 4370.34 |

**Primary model บอก SELL ทุกครั้ง ขณะที่ราคาวิ่งขึ้น 21 ดอลลาร์**
ระบบรอด เพราะ trailing stop ปิดไม้ก่อนขาดทุนหนัก ไม่ใช่เพราะทายถูก

สาเหตุที่เป็นไปได้ เรียงตามความน่าจะเป็น:

1. **Label ผิดทิศ** — เผลอสลับ class 0/1 หรือ `classes_` ไม่ใช่ `[0,1]`
   (exporter ใน repo นี้ตรวจให้แล้ว และจะปฏิเสธไฟล์ที่ผิด)
2. **Feature scale drift** — เทรนตอนทองอยู่ 1800 แต่เทรดตอน 4300
   ฟีเจอร์ที่ไม่ normalize (MACD ดิบ, ระยะทางเป็นดอลลาร์) กลายเป็นค่าที่โมเดล
   ไม่เคยเห็น แล้วมันจะตกไปที่ leaf เดิมตลอด → คำตอบเดิมตลอด
   **V5 หาร MACD และระยะทางทุกตัวด้วยราคา จึงไม่มีปัญหานี้**
3. **Timezone ไม่ตรง** — log แสดง `13:35` ขณะที่นาฬิกาเครื่องคุณคือ `20:36` กรุงเทพ
   เซิร์ฟเวอร์โบรกเกอร์ = UTC+2/+3, เครื่องคุณ = UTC+7
   ถ้าเทรนด้วย CSV เวลา UTC หรือเวลาไทย → `hour_sin/hour_cos` ผิดทุกแถว

**V5 มี canary ในตัว:** ถ้าสัญญาณออกทางเดียวกัน 25 ครั้งติด EA จะเตือนใน log ทันที

## 4. 🟠 TP:SL = 10:1 คือ TP ที่ไม่มีวันถึง

`TP Money = $100`, `SL Money = $10`, `Lot 0.05`

```
TP $100 → ราคาต้องวิ่ง $20.00
SL  $10 → ราคาวิ่งสวน  $2.00
```

ATR(14) บน XAUUSD M5 อยู่ราว **$1.5 – $4.0**
TP ของคุณคือ **~10 ATR** — บน M5 มันแทบไม่เกิด

ในสกรีนช็อตที่สี่คุณลดเหลือ `TP = $5` ซึ่งสมเหตุสมผลกว่ามาก
แต่ประเด็นจริงคือ: **stop ที่ผูกกับจำนวนเงินไม่รู้ว่าตลาดผันผวนแค่ไหน**
$10 คือ stop กว้างตอนตลาดนิ่ง และคือ stop แคบมากตอนข่าว

**แก้ยังไง:** `InpStopMode = SNP_STOP_ATR` (ค่าเริ่มต้นของ V5)

## 5. 🟠 `TP Points 4.0 / SL Points 2.0` — ตัวเลขนี้เป็นไปไม่ได้

ถ้าโบรกเกอร์ให้ทองเป็น 2 ตำแหน่ง → 1 point = $0.01
```
SL 2 points = $0.02   ←  แคบกว่าสเปรดประมาณ 20 เท่า
```
ออเดอร์จะโดนปิดทันทีที่เปิด หรือถูกเซิร์ฟเวอร์ปฏิเสธเพราะต่ำกว่า `SYMBOL_TRADE_STOPS_LEVEL`

โชคดีที่ในสกรีนช็อตคุณปิดโหมดนี้ไว้ แต่มันแสดงว่าโค้ดไม่เคยตรวจ stops level เลย
**V5 อ่าน `SYMBOL_TRADE_STOPS_LEVEL` + `SYMBOL_TRADE_FREEZE_LEVEL` และจะข้ามไม้นั้น
ถ้าโบรกเกอร์บังคับขยาย SL เกิน 50% ของที่ขอ**

## 6. 🟠 Tick Volume ไม่ใช่ Volume

`vol_delta` และ `rvol_20` คำนวณจาก tick volume = **จำนวนครั้งที่ราคาขยับ**
ไม่ใช่ปริมาณเงิน และแต่ละโบรกเกอร์นับไม่เท่ากัน เพราะแต่ละเจ้ามี liquidity provider คนละชุด

ผลที่ตามมาที่คนมองข้าม: **โมเดลที่เทรนบน tick volume ของโบรกเกอร์ A
จะใช้กับโบรกเกอร์ B ไม่ได้** ถึงจะเป็น XAUUSD เหมือนกัน

V5 ยังเก็บ 2 ฟีเจอร์นี้ไว้ (มันมีข้อมูลจริงเรื่อง activity อยู่บ้าง) แต่:
- ทั้งคู่เป็น **ratio** ไม่ใช่ค่าดิบ → ทนต่อความต่างของ scale ระหว่างโบรกเกอร์
- ถ้าจะย้ายโบรกเกอร์ **ต้องเทรนใหม่** ไม่มีข้อยกเว้น

## 7. 🟠 40 ฟีเจอร์บน M5 = สนามเด็กเล่นของ Overfitting

ปัญหาไม่ได้อยู่ที่จำนวน 40 แต่อยู่ที่ **การ validate**

label ที่ตอบว่า "ราคาจะไปทางไหนใน 12 แท่งข้างหน้า" ใช้ข้อมูลถึงแท่ง t+12
ถ้าแบ่ง train/test แบบ KFold ธรรมดา แถวที่ t อยู่ใน train และแถวที่ t+3 อยู่ใน test
→ **อนาคตรั่วเข้า train set** backtest จะสวยงามและไม่มีวันเกิดขึ้นจริง

`tools/train_two_tier.py` ใช้ **purged + embargoed walk-forward CV**
พร้อม holdout ก้อนสุดท้ายที่ไม่ถูกแตะเลยจนถึงบรรทัดสุดท้าย

ตัวอย่างจริงจากการรันไปป์ไลน์นี้บนข้อมูลสังเคราะห์ (random walk = ไม่มี edge จริง):

```
THRESHOLD SWEEP (out-of-fold)     FINAL HOLDOUT (ไม่เคยแตะ)
  thr=0.70  PF=1.659                thr=0.70  PF=0.616
  thr=0.75  PF=1.763                thr=0.60  PF=0.891
```

**ตัวเลข out-of-fold สวยมาก holdout พังทันที** — นี่คือหน้าตาของ overfitting
ถ้าไปป์ไลน์ของคุณไม่มีตัวเลขคอลัมน์ขวา คุณไม่รู้เลยว่ากำลังดูอันไหนอยู่

## 8. 🟡 สถาปัตยกรรม Python คือความเสี่ยงเชิงระบบ

`run_bot_ui.py` (18 KB) รวม GUI thread + trading loop + trailing stop ไว้ในโปรเซสเดียว
นอกเทอร์มินัล

- เน็ตหลุด → trailing loop ตาย → ออเดอร์ลอยไม่มี SL เลย (เพราะ SL เป็น client-side)
- tkinter ค้าง (ลาก scrollbar, resize) → main loop หยุด
- Python crash → ไม่มีใครดูแลออเดอร์
- Windows Update รีสตาร์ท → เหมือนกัน

**V5 แก้ที่ราก:** SL/TP ทุกตัวถูกส่งไปอยู่ที่ **เซิร์ฟเวอร์โบรกเกอร์**
ต่อให้คอมระเบิด stop ยังทำงาน ส่วนการเช็คด้วยเงินเป็นแค่ **ตาข่ายสำรอง**
และถ้า EA เจอออเดอร์ของตัวเองที่ไม่มี SL มันจะใส่ให้ทันที

## 9. 🟡 ต้นทุนไม่ได้อยู่ใน label

ถ้า label คือ "แท่งถัดไปขึ้นหรือลง" โดยไม่หักสเปรด+คอมมิชชั่น
โมเดลจะเรียนรู้ edge ขนาด 5 cent ซึ่งหายไปหมดตอนจ่ายค่าสเปรด 30 cent

`train_two_tier.py` ใส่ต้นทุนเข้าไปใน **barrier** ตั้งแต่ตอนสร้าง label
(`--cost` เป็นหน่วยราคา, `fetch_mt5_history.py` พิมพ์ median spread จริงให้)

## 10. ⚪ สิ่งที่ V4 ทำถูก และ V5 เก็บไว้ทั้งหมด

พูดให้แฟร์ — โครงสร้างใหญ่ของคุณถูกต้อง:

- **Two-tier meta-labelling** เป็นของจริงในวงการ quant ไม่ใช่ของเล่น
- **Sine/Cosine time encoding** ถูกวิธี วงจรเวลาไม่มีรอยต่อที่เที่ยงคืน
- **Money-based UI** ใช้งานง่ายจริง เทรดเดอร์คิดเป็นเงิน ไม่ได้คิดเป็น pip
- **มี trailing stop ตั้งแต่แรก** หลายคนไม่มีด้วยซ้ำ
- **แยก build_features / train_meta_model / run_bot ออกจากกัน** เป็นระเบียบ

ปัญหาทั้งหมดข้างบนอยู่ที่ **การ calibrate ตัวเลข** และ **การ validate**
ไม่ใช่ที่แนวคิด แนวคิดคุณถูกแล้ว

## สรุปสิ่งที่ต้องทำ ก่อนคิดถึงเงินจริง

1. เลิกใช้ trailing เป็นดอลลาร์ → ใช้ ATR (`SNP_TRAIL_ATR`)
2. เลิกใช้ threshold 0.35 → เลือกจาก threshold sweep ที่รันจริง
3. หาว่าทำไม primary ถึงตอบ SELL ตลอด (label / scale / timezone)
4. เทรนใหม่ด้วย purged CV + ต้นทุนใน label
5. รัน `parity_check.py` ให้ผ่านทั้งสองด่าน
6. Strategy Tester ด้วย real ticks + คอมมิชชั่นจริง
7. Demo forward test อย่างน้อย 1 เดือนเต็ม
8. ค่อยคุยเรื่องเงินจริง

**ข้อ 1 ข้อเดียวน่าจะเปลี่ยนผลลัพธ์มากกว่าการ tune โมเดลทั้งปี**
